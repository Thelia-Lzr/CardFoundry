# 06｜本地数据与通用规范

## 1. IndexedDB 数据库

数据库名称建议为 `BoardGameDesignerDB`，所有临时数据保存在浏览器本地。

| Object Store | 主要内容 |
|---|---|
| projects | 项目名称、描述、创建时间、更新时间 |
| boards | 版图尺寸、背景和基础信息 |
| boardObjects | 版图对象坐标、样式、绑定和行为 |
| cards | 单卡字段、富文本和图片引用 |
| decks | 卡组基础信息 |
| deckEntries | 卡组与单卡关系、数量 |
| assets | 图片和其他本地二进制资源 |
| playtestSessions | 独立试玩会话、牌序和游戏日志 |
| history | 撤销、重做和自动保存快照 |
| settings | 用户偏好、默认尺寸和快捷键 |

## 2. 自动保存

- 编辑操作后延迟约 500ms 保存，避免每次输入都写库。
- 页面关闭或切换项目之前执行一次同步保存。
- 顶部显示保存状态：`已保存`、`保存中`、`保存失败`。
- 保存失败时保留内存数据，并提供重试按钮。
- 最近的历史快照用于恢复异常关闭前的编辑内容。

## 3. 数据引用规则

- 每个项目、版图、对象、单卡和卡组均使用稳定 ID。
- 版图对象引用单卡或卡组 ID，不直接复制完整内容。
- 卡组通过 `deckEntries` 引用单卡 ID 和数量。
- 删除被引用资源时不静默删除引用，改为标记缺失并提供修复入口。
- 试玩实体卡牌使用独立实例 ID，避免改变设计数据。

## 4. 通用交互规范

- 破坏性操作使用确认弹窗，例如删除项目、覆盖导入。
- 可撤销操作显示短暂 Toast，并支持 `Cmd/Ctrl + Z`。
- 所有拖拽目标在悬停时显示可放置状态。
- 无数据页面提供下一步操作按钮，而不是只显示空白。
- 错误提示说明原因和可执行的解决方式。
- 颜色、字号、按钮和间距使用统一设计令牌。

## 5. 数据安全与备份提示

浏览器缓存被手动清理、无痕窗口关闭或浏览器策略变更时，本地数据可能丢失。应用应在首次创建项目时提示用户定期导出 `.bgdesign` 文件进行备份。

## 6. MVP 优先级

第一阶段优先实现：

1. 三个主导航页面和设计二级导航。
2. 版图四类核心对象及属性编辑。
3. 单卡富文本编辑、飞书粘贴和 XLSX 导入。
4. 卡组成员管理和 XLSX 导入。
5. 试玩中的抽牌、移动、翻牌和弃牌。
6. IndexedDB 自动保存。
7. 完整项目导入和导出。

后续可扩展：Token、骰子、计分板、规则脚本、打印排版、多人联机和试玩回放。
