# 05｜文件导出页

## 1. 页面目标

用于导入、导出和备份完整桌游设计，也支持单独处理版图、单卡、卡组及试玩状态。

## 2. 页面布局

```text
┌──────────────────────────────────────────────────────────────────┐
│ 文件导出   导入设计文件   导出完整项目   导出当前对象   导入历史  │
├──────────────────────┬───────────────────────────────────────────┤
│ 文件操作               │ 当前项目内容概览                          │
│                        │ 版图、单卡、卡组、图片、试玩会话统计        │
└──────────────────────┴───────────────────────────────────────────┘
```

## 3. 文件操作区

### 3.1 导出操作

- 导出完整桌游设计文件。
- 仅导出当前版图。
- 仅导出全部单卡或选中单卡。
- 仅导出当前卡组。
- 导出试玩状态。
- 导出图片资源包。

默认完整项目文件扩展名：`.bgdesign`。

### 3.2 导入操作

- 拖拽文件到导入区域。
- 点击选择本地文件。
- 读取最近导入记录。
- 导入前验证文件版本和完整性。

## 4. 项目内容概览

| 统计项 | 内容 |
|---|---|
| 版图 | 版图总数和当前版图名称 |
| 单卡 | 单卡总数 |
| 卡组 | 卡组总数和卡牌总数 |
| 图片资源 | 已上传图片数量和占用空间 |
| 试玩会话 | 已保存试玩状态数量 |
| 最近保存 | 最近一次自动保存时间 |

提供“检查项目”按钮，扫描缺失引用、无效图片和异常卡组数量。

## 5. 推荐文件结构

`.bgdesign` 建议为带版本信息的 ZIP 容器：

```text
manifest.json
project.json
boards.json
board-objects.json
cards.json
decks.json
deck-entries.json
assets/
playtest/
```

### 5.1 manifest.json

保存文件格式版本、应用版本、项目 ID、创建时间、导出时间和资源清单。

### 5.2 数据内容

- `boards.json`：版图名称、尺寸、背景和对象引用。
- `board-objects.json`：对象类型、坐标、尺寸、样式、绑定关系和行为配置。
- `cards.json`：卡名、富文本效果、图片引用、元数据。
- `decks.json`：卡组名称、描述和样式。
- `deck-entries.json`：卡组与单卡的关系及数量。
- `playtest/`：可选试玩会话和牌序。

## 6. 导入流程

```text
拖入或选择文件
  ↓
验证格式、版本和完整性
  ↓
显示项目摘要
  ↓
选择冲突处理方式
  ↓
确认导入
  ↓
导入完成并刷新项目
```

### 6.1 导入摘要

确认前显示文件名和大小、文件版本、创建时间、版图数量、单卡数量、卡组数量、图片资源数量、试玩会话数量及错误警告数量。

### 6.2 冲突处理

- 覆盖当前项目。
- 作为新项目导入。
- 合并到当前项目。
- 跳过重复对象。

合并时使用 ID 优先、名称辅助匹配；覆盖前必须显示明确确认弹窗。

## 7. 导入错误处理

- 文件格式不支持：提示支持的扩展名。
- 文件损坏：提示重新导出或选择其他文件。
- 文件版本过旧：提供迁移后导入或取消。
- 缺失图片：保留卡牌文字，显示图片占位符。
- 缺失单卡引用：保留卡组成员并标记为待处理。
- 重复对象：按用户选择覆盖、跳过或合并。

导入完成后显示结果摘要，例如：“成功导入 2 个版图、48 张单卡、4 个卡组；3 张图片缺失”。

## 8. 浏览器下载与本地安全

- 导出文件通过浏览器下载，不上传服务器。
- 导入文件只在本地解析。
- 导出前提示当前自动保存状态。
- 图片等二进制资源随项目文件打包。
- 大文件导出显示进度状态。

## 9. 页面验收标准

- 可以完整导出并重新导入版图、单卡、卡组和图片资源。
- 导入后富文本颜色、底色、布局和绑定关系不丢失。
- 支持新项目导入、覆盖导入和合并导入。
- 文件损坏、版本异常和缺失资源都有明确提示。
- 导入导出过程不依赖服务器。
